# Автосалон — лабораторна робота (Node.js)

Предметна область: **марки машин, комплектація, клієнт, продаж, додаткові опції**.

## Запуск

```bash
npm install
npm start
```

Додаток: http://localhost:3000

## Структура проєкту

| Файл | Призначення |
|---|---|
| `server.js` | Express-сервер, усі маршрути (CRUD для 5 таблиць), централізована серверна валідація |
| `entities.js` | Опис сутностей: поля, типи, валідатори, правила видалення |
| `validators.js` | Бібліотека валідаторів (обов'язковість, довжина, число, email, телефон, дата, унікальність, зовнішній ключ) |
| `views.js` | HTML-шаблони (списки + форми з виведенням помилок під полем) |
| `db.js` | Файлове JSON-сховище з початковими даними (`data/db.json`, створюється автоматично) |

## Таблиці та зв'язки

- **Марки машин** (brands) — назва, країна
- **Комплектації** (trims) — марка (FK), назва, двигун, потужність, КПП, ціна
- **Клієнти** (clients) — ПІБ, телефон, email
- **Додаткові опції** (options) — назва, ціна
- **Продажі** (sales) — клієнт (FK), комплектація (FK), дата, знижка + вибрані опції (зв'язок M:N через sale_options)

## Серверна валідація

У HTML-формах **немає жодного атрибута `required`** — усі перевірки виконуються
на сервері. При помилках форма повертається з введеними значеннями та
повідомленнями українською під кожним полем (HTTP 400).

### Правила по полях

**Марки машин**
- Назва — обов'язкова, 2–30 симв., унікальна
- Країна — обов'язкова, 2–40 симв.

**Комплектація**
- Марка — обов'язкова, має існувати в БД (зовнішній ключ)
- Назва — обов'язкова, 2–40 симв.
- Двигун — обов'язковий, число 0.6–8.0 л (формат `2.0`)
- Потужність — обов'язкова, ціле число 40–1500 к.с.
- КПП — обов'язкова, одне зі значень: Механіка / Автомат / Робот / Варіатор
- Ціна — обов'язкова, число > 0

**Клієнт**
- ПІБ — обов'язкове, 5–60 симв., унікальне
- Телефон — обов'язковий, формат `+380XXXXXXXXX`
- Email — обов'язковий, формат email, унікальний

**Додаткова опція**
- Назва — обов'язкова, 3–50 симв., унікальна
- Ціна — обов'язкова, число > 0

**Продаж**
- Клієнт, комплектація — обов'язкові, існують у БД (зовнішні ключі)
- Дата — обов'язкова, формат РРРР-ММ-ДД, не пізніше сьогоднішньої
- Знижка — обов'язкова, ціле число 0–50 %
- Додаткові опції — необов'язкові (чекбокси, зв'язок багато-до-багатьох)

### Посилальна цілісність при видаленні (теж перевіряється на сервері)

- Марку не можна видалити, якщо є її комплектації
- Комплектацію не можна видалити, якщо вона входить у продажі
- Клієнта не можна видалити, якщо у нього є продажі
- Опцію не можна видалити, якщо її вибрано у продажах
- Продаж видаляється разом із вибраними опціями

## Маршрути

| Метод і шлях | Дія |
|---|---|
| `GET /:table` | список записів |
| `GET /:table/new` | форма додавання |
| `POST /:table` | створення (з валідацією) |
| `GET /:table/:id/edit` | форма редагування |
| `POST /:table/:id` | збереження змін (з валідацією) |
| `POST /:table/:id/delete` | видалення (з перевіркою посилань) |

## Скидання даних

Видаліть `data/db.json` і перезапустіть сервер — база відновиться з початковими даними.


## Розгортання на Railway

1. Завантажте папку проєкту в репозиторій GitHub (без `node_modules`).
2. На [railway.app](https://railway.app): **New Project -> Deploy from GitHub repo**.
3. У **Settings -> Networking -> Generate Domain** створіть публічну адресу.

Railway сам виконує `npm install` і `npm start`; порт читається зі змінної `PORT`.
Тестові акаунти (admin/admin123, manager/manager123, visitor/visitor123) вже є у файловій базі.

**Збереження даних.** Записи зберігаються у `data/db.json` усередині контейнера.
Щоб дані не зникали після передеплою: **Settings -> Volumes** (mount path `/data`)
та змінна `DATA_DIR=/data` у **Variables**.
